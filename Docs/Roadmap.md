- **포함·경계:** 현재 상태·다음 작업·단계 계획·남은 확인/선택/검증 사항·중요 결정을 관리한다. 상세 규칙·환경 조사·시험 로그·일일 활동 전체는 옮겨 적지 않는다.

- **검증:** 현재·다음 작업과 허용 범위가 맞는지, 완료 주장에 해당 확인 결과가 연결되는지, 사실 확인·선택 완료·가설 검증을 서로 대신하지 않는지와 담당·해결 시점의 누락을 확인한다. 일정에는 준비·학습·검증 시간을 포함하고 목표·실측을 구분한다. 과거 제안은 남기더라도 현재 채택 여부가 분명해야 한다.

- 이번 작업: 사용자 지시에 따라 `main` 초기화, 저장소별 작성자 설정, Git 자체 제외/속성 검사와 9파일 검토를 수행해 첫 로컬 커밋으로 남긴다. [실행·검증 기록](Validation/Environment.md#로컬-git-초기화첫-커밋--2026-10-30)을 참조한다. 커밋 식별자는 이 기록을 포함한 최초 커밋이며 실제 SHA와 종료 상태는 Git 이력·종료 보고로 확인한다. 원격 생성·업로드·다른 장비 전달·설치·빌드는 미실시다.

## 일정 전제

**확정 요구:** 4주 MVP 목표. **제안:** 주 6작업일×4주×하루 6시간=144시간을 계획 기준으로 사용한다. 주당 작업일·실제 착수일은 미정이다. 전체 병행 작업 12시간을 본 프로젝트 전용 시간으로 계산하지 않는다. 환경 준비·학습·시험·수정·기록도 이 시간에 포함한다.

주차는 배정 가설이다. 초기 독립 접속과 공격 검증 소요를 확인한 후 재산정한다. 과거 임시 문서의 기능 ID·24일 상세 배정은 자동 계승하지 않는다.

4주를 계산할 기준일은 D04-S에서 정한다. 기준일 이후의 준비·설치·학습도 일정에 포함하며 환경 준비가 길어진다는 이유로 시작일을 조용히 뒤로 옮기지 않는다. 그 이전 조사·문서 작업은 사전 준비로 별도 표시한다. 아직 기준일이 없으므로 현재를 자동으로 1주차로 계산하지 않는다.

공유 대상은 현재 문서·Git 관리 파일·아래 정책의 모델 추천 스킬 스냅샷부터 시작한다. 사용자 전체 설정·인증 정보를 공유 대상으로 삼지 않는다. 별도 인수인계 문서를 만들지 않고 Roadmap에 마지막 결과·남은 일·다음 행동을 갱신한다.

파일/이력 전달과 채팅 Handoff는 별개다. Handoff는 같은 Git 저장소의 대상 프로젝트 등록 등 지원 조건을 실행 시 확인하며, 대상 worktree가 `C:\CoopRPG` 경로 지침과 맞는지도 먼저 확인한다. 경로가 다르면 먼저 알리고 임의로 새 폴더를 만들지 않는다. 조건이 맞지 않으면 저장소를 전달하고 새 로컬 채팅에서 기존 문서를 읽는 대안을 검토한다.

이관 후에는 기능별 주 편집 장비 하나를 정한다. 기본은 데스크탑 구현·노트북 시험이며 같은 기능의 동시 수정을 피한다. 데스크탑 사양·저장 공간·처리 속도는 아직 미확인이므로 주 개발 장비로 쓰려는 사용자 의향과 실제 적합성 검증을 구분한다. 이 순서는 4주 시작일을 자동 확정하거나 환경 준비 시간을 일정 밖으로 빼는 근거가 아니다. 준비 작업을 세부 단위로 나누고 각 착수 시 시간 한도를 정한다.

## D02-S 폴더·Git·스킬 전달 정책

2026-10-30 정책 정리 요청에 따른 기술 정책은 **허용 범위 안의 AI 판단**이다. 같은 날 후속 사용자 답변으로 GitHub의 `Razria93/CoopRPG` 공개 저장소와 현재 작성자 사용을 **사용자 선택으로 확정**했다. 관리 파일·프로젝트 내 스킬 사본 준비에 이어 로컬 Git 초기화·첫 커밋을 허용받았다. 실제 엔진 경로는 데스크탑 조사 후 선택하며 게임 프로젝트·원격 저장소는 생성하지 않았다.

| 위치 | 역할·관리 기준 |
|---|---|
| `C:\CoopRPG` | 프로젝트·향후 Git 저장소 루트. 기존 문서를 옮기지 않고 양쪽 PC에서 이 경로를 우선 사용 |
| `Game/CoopRPG.uproject` | 향후 게임 프로젝트 위치로 선택. Config·Content·Source·필요한 Plugins/Build는 Game 아래에 두며 게임 생성은 데스크탑에서 허용 후 수행 |
| `Docs/` | 현재 목적·진행·환경·검증 기록 유지. Architecture·Cases·Evidence는 내용이 생길 때만 생성 |
| `Tools/Skills/recommend-model/SKILL.md` | Git에 추적하는 스킬 기준 원본. 개인 스킬과 바이트·SHA-256 일치 확인. 데스크탑 설치는 미실시, 로딩은 미검증 |
| 저장소 밖의 짧은 로컬 SSD 경로 | 엔진 소스/바이너리·엔진의 별도 Git 이력. OneDrive 동기화 폴더와 게임 저장소 안에 엔진을 두지 않는 안으로 선택. 데스크탑의 실제 드라이브/경로·공간은 재조사 후 결정 |
| `Artifacts/` 또는 명시한 외부 위치 | 향후 로컬 패키지·대형 원시 증거. Git 추적 제외, 검증 기록에서 보관 위치·실행/빌드 ID 연결. 이번에 생성하지 않음 |

**일반 Git·제외 정책:** 기본 브랜치는 `main`. 현재 문서 6개, 채택한 `.gitignore`/`.gitattributes`, 스킬 원본은 일반 Git에 둔다. 게임 생성 후 `.uproject`, Source의 코드/Build.cs/Target.cs, Config의 프로젝트 기본 설정, 권한이 확인된 Content·Plugins와 필요한 Build 입력을 추적한다. `Game/Build`를 생성물로 통째로 제외하지 않는다. 루트 Docs는 게임 프로젝트 바깥에 유지한다.

전역/시스템 설정을 바꾸지 않고 로컬 저장소를 `main`으로 초기화했다. 줄바꿈 변환으로 스킬 사본의 바이트가 달라지지 않도록 `.gitattributes`에 Markdown의 `*.md text eol=lf`를 작성했고 Git의 속성·색인/작업 파일 검사로 적용을 확인했다. 근거는 [Git 속성 안내](https://git-scm.com/docs/gitattributes)다. 전달 시에는 해당 커밋의 스킬 원본과 대상 사본을 비교한다.

`.gitignore`에 반영한 제외 범위는 `.vs`, Game의 Binaries·Intermediate·Saved·DerivedDataCache, Game 바로 아래의 생성된 `.sln`/`.slnx`/`.vcxproj`/`.vcxproj.filters`, Artifacts와 임시 파일이다. IDE 캐시·사용자 설정은 제외하되 도구나 외부 플러그인의 원본 IDE 프로젝트를 확장자만으로 일괄 제외하지 않는다. 플러그인의 재생성 가능한 중간 산출물도 제외하되, 소스 없는 플러그인의 필수 배포 바이너리는 재생성 가능하다고 가정하지 말고 D03에서 의존성·권한 확인 후 별도로 판단한다. 패키지의 `.exe`·`.pak` 등을 원본 입력과 구분하고 확장자만으로 모든 의존 바이너리를 일괄 제외하지 않는다. 키·토큰·개인별 설정·엔진을 포함하지 않는다. `Docs/X`는 현재 없으며 다시 나타나면 원본을 보존하고 초기 커밋 범위에서 제외한다. 제외는 삭제 지시가 아니다.

**LFS 정책:** 게임 자산 `.uasset`·`.umap`은 첫 추적 전부터 LFS 대상으로 선택하고, `.gitattributes`는 일반 Git에 추적한다. 작성한 패턴은 `*.uasset filter=lfs diff=lfs merge=lfs -text`, `*.umap filter=lfs diff=lfs merge=lfs -text`다. 추가 원본 미디어는 실제로 필요한 파일·권한·공유 저장소의 용량/전송 조건을 확인한 뒤 선택하며 `.png`·`.wav`·모든 Docs를 일괄 LFS로 넣지 않는다. 패키지·대형 영상/트레이스는 초기 Git 공유에서 제외한다.

문서만 있는 초기 커밋에는 LFS 바이너리 객체가 필요 없다. LFS 자산을 체크아웃·추가·공유할 장비와 공유 경로에서 사용 전에 지원·버전을 확인하고, 허용 후 저장소별 LFS 설정을 적용한다. 패키지 클라이언트만 실행하는 시험 장비에는 Git/LFS 구성을 요구하지 않는다. 초기 이력만 전달됐다는 이유로 자산 전달 완료로 처리하지 않고 대상에서 포인터가 아닌 실제 객체를 받을 수 있는지 확인한다. 자동 이력 변환·기존 이력 재작성은 이 정책에 포함하지 않는다.

**스킬 전달:** 개인 `recommend-model`을 `Tools/Skills/recommend-model`에 원문 그대로 복사하여 초기 커밋 후보에 포함했다. 이 경로를 프로젝트가 전달하는 기준 원본으로 삼는다. 이 보관 경로에 있다는 것만으로 스킬 로딩 완료로 보지 않으며, 데스크탑 전달을 허용받은 뒤 사용할 개인 스킬 경로에 복사하고 로딩 여부와 SHA-256 일치를 확인한다. 현재 설정 유지·자료 확보 우선 판단과 모델/추론 수준을 자동 변경하지 않는 추천 전용 원칙을 유지한다. 개인 계정 경로는 장비마다 다를 수 있다. 기존 동명 스킬이 있으면 차이를 확인하고 무조건 덮어쓰지 않는다. 개인판 변경을 자동 반영하지 않고 프로젝트에 채택한 변경만 기준 원본에 반영한다. 이후에는 스킬을 사용하는 장비에서 사용 전에 갱신하며, 시험 전용 장비까지 매번 동기화하지 않는다. 사용자 전체 `.codex` 설정은 전달하지 않는다. 이 한 개 스킬 때문에 플러그인 패키지나 설치 스크립트를 만들지 않는다.

**공유·인계:** 초기 추적 파일은 기존 문서 6개 + `.gitignore`/`.gitattributes` + 스킬 원본 1개, 총 9파일이다. `git add .`로 전체 폴더를 무검토 추가하지 않고 제외 적용과 staged diff를 확인한다. **사용자 선택:** 계정 `Razria93`, 새 저장소 이름 `CoopRPG`, 공개, 현재 작성자 이름 `Razria-Notebook`과 등록 이메일 사용. 이메일 원문을 프로젝트 문서에 추가하지 않는다. 로컬 첫 커밋 허용과 원격 작업의 허용은 구분한다. 원격 저장소 생성·업로드·Git 전송 인증은 미실행·미검증이다. 공개 직전 실제 포함 목록·내용을 다시 확인한다. 대상에서 같은 커밋·추적 파일·스킬 내용과 실제 실행 호스트/경로를 확인한 뒤 인계 완료로 기록한다.

근거: [Epic 디렉터리 안내](https://dev.epicgames.com/documentation/en-us/unreal-engine/unreal-engine-directory-structure), [Git LFS 공식 안내](https://git-lfs.com/). 설치 여부만으로 최신 권고 충족을 가정하지 않는다. 공식 LFS가 보안 수정판 3.8.1을 안내하고 있어 기존 3.7.1의 준비 조치는 [Environment](Validation/Environment.md#d02-s-lfs-도구와-스킬-표본--2026-10-30)에 남긴다. 이번에는 LFS 설정·업데이트를 수행하지 않는다.

첫 기술 검증의 적용 범위·완료 기준 원본은 [Validation](Validation/Index.md#첫-기술-검증-범위와-통과-기준)이며, 준비·문서·코드 존재를 시험 통과로 계산하지 않는다.

## 남은 확인·선택·검증 사항

기존 D01~D12는 주제 번호로 유지하고, F는 미확인 사실, S는 선택할 사항, H는 검증할 가설을 뜻한다. D01-F는 부분 확인, D01-S는 조건부 구성안 확보, D02-S는 기술 정책·공유 방식·작성자 선택 완료 및 실행 대기이며 나머지는 미해결이다. 기존 확인 사실은 보존하고 F에서는 남은 정보와 사용 전 재확인이 필요한 값만 조사한다. 분류·담당 지정은 실행 허용이나 결과 확인을 뜻하지 않는다. 주차는 시작 기준일(D04-S)을 정한 뒤 적용한다.

- **담당 원칙:** AI는 접근 가능한 자료 조사·비교·기술 판단·허용된 실행과 기록을 맡는다. 사용자는 본인 일정·핵심 범위·비용 결정을 맡고, AI가 접근할 수 없는 장비·구매 내역·현장 조작을 제공한다. 조사로 확인할 수 없는 정보만 질문한다. 시험 참여자 일정은 사용자가 조율하며 이 목록으로 참여가 확정된 것은 아니다.
- **허용 범위:** 현재는 문서 정비·읽기 조사만 가능하다. 아래 구현·빌드·게임 시험은 해당 작업이 허용되고 선행 선택을 마친 뒤 진행한다. 이미 허용된 범위의 일상적 기술 판단에 반복 승인을 요구하지 않는다.
- **해결 기록:** 사실은 날짜·방법·결과를 Environment에, 선택은 주체·근거·영향을 이 문서와 해당 원본에, 가설은 조건·기대값·실제 결과·판정을 Validation에 남기고 해당 행에 연결한다. 실패로 가설이 기각되어도 조사 결과는 남기며 후속 조치를 정한다. 선택 완료만으로 관련 가설을 통과 처리하지 않는다.
