## 판단과 변경 이력

### R001 · 2026-11-05 · 개발 운영 과정을 포트폴리오에 포함

- 발생일·기록일: 모두 2026-11-05.
- 요청 주체와 근거: 사용자가 이 대화에서 MVP의 일정 준수·학습 소화·범위 축소·대응 과정을 기록하고 최종 포트폴리오에 표현하라고 요청했습니다.
- 앞선 상태: 강의·일별 작업·검증·문서화 계획안이 있었습니다. 이후의 실제 진도와 변경 결과를 누적할 기록은 아직 마련되지 않았습니다.
- 이번 반영: 최초 계획은 보존하고, 예정/실제 표·중간 목표 판정·변경 이력·최종 사례 초안을 마련했습니다.
- 범위 영향: 개발 운영의 설명과 기록을 추가했습니다. 게임 기능을 진행 중 축소한 결정이나 모든 초기 수치의 확정으로 기록하지 않습니다.
- 실제 역할: 사용자 — 개발 운영 과정도 결과물에 포함할 필요를 제시. AI — 기록 구조·문서 초안·참조 검사 수행.
- 현재 결과: 기록 파일이 준비됐습니다. 이 방식으로 개발을 운영한 효과와 제출 결과는 아직 확인되지 않았습니다.
- 관련 자료: [기록 안내](../README.md), [최종 편집 구성](#portfolio-output).

### R002 · 2026-11-05 · 논의 이력과 CoopRPG 구조 보완 분석

- 발생일·기록일: 모두 2026-11-05. 당시 대화 6개 메인 턴을 조회하여 출발 이유부터 현재 요청까지 확인했습니다.
- 사용자 요구: 학습·작업과 함께 기록 갱신, 하루의 추가 완료·미달과 대응 확인, 팀 소통에 쓸 수 있는 현재 상태, 기존 구조와 자동화 필요의 분석·계획 작성.
- 확인한 기반: 로컬 CoopRPG는 `chore/game-bootstrap`의 `91683e7`, clean 상태입니다. 최소 C++ 모듈과 Game/Editor 타깃, 기존 저장소 CI·검증·PR 절차가 있습니다. 게임플레이·Server 타깃은 아직 없으며 이번에는 게임 시험을 실행하지 않았습니다.
- 발견: 기존 4주/하루6h 및 다운·부활 제안과 최신 제출 일정/축소 범위가 병존합니다. 강의·채용 목적·일별 기록은 UE5_Practice에 분리되어 있습니다.
- AI 제안: 기존 기반 유지, Project/Roadmap/Validation 정합화, Development 원본 통합, 일일 차이와 다음 행동 기록, 실제 반복 비용에 따른 작은 자동화. 필수 보완 시간 한도는 3~4h 제안입니다.
- 현재 결과: [구조 검토와 보완 계획](#discussion-history)을 작성하고 이 기록에 연결했습니다. CoopRPG의 코드·문서·원격 저장소와 자동화 예약은 변경하지 않았습니다.
- 확인: 문서/CSS 7개·로컬 참조 44건의 정적 검사에서 오류·경고 0건, 대화 턴 6개·보고서 절 12개·기존 일별 표 19행의 대응과 최초 계획 보존을 확인했습니다. 조사 종료 시 CoopRPG 작업 트리도 clean이었습니다. 브라우저 화면 검수와 게임 시험은 포함하지 않았습니다.
- 의미 구분: 강의 선택·일정 정밀화·부활 제외 제안은 준비 단계의 판단입니다. 실제 개발 지연을 해결한 사례나 운영 개선 효과로 소급하지 않습니다.
- 다음 행동: U1~U4의 최소 정합화 후 기초 진단·V01 진행. 최신 원격 PR/머지 상태와 실제 이해·실행 속도는 해당 작업에서 확인합니다.

## 매일 기록하고 팀에 전달하는 방법

작업 시작 때 오늘 기대 결과와 완료 조건 하나를 정한다. 의미 있는 결과가 바뀐 작업 턴에는 이 기록을 함께 갱신하고 하루 끝에 [일일 양식](#daily-template)으로 요약한다. 약10분의 일일 정리와 중요한 사례20~40분은 초기 제안이며 당일 총예산 안에 포함한다. 단순 대화·미관측 활동의 실적을 만들지 않는다.

- 계획대로 완료: 결과·근거·판정. 추가 완료: 이유·원목표 영향. 덜 된 것: 확인 원인/추정·남은 작업·이월.
- 학습 확인: 수강과 설명/직접 수정/실행을 구분. 검증: 규칙·빌드·시험/실행 ID와 실제 통과/실패/미실행.
- 변경: 원목표·원기한/현재 예상/실제 통과, 검토한 대안·선택·손실·후속 결과. 제외를 완료로 계산하지 않음.
- 협업: 담당·현재 막힘·다음 행동·다음 확인 시점과 필요한 도움. 새 팀원이 README→Roadmap→기록/시험 근거로 이동하도록 유지.
- 기여: 사람이 목표/검토/실행한 범위와 AI의 조사·작성·수정·시험을 구분. 절감률은 비교 실측 없으면 쓰지 않음.
- 운영 원본은 이 파일 한 곳이다. 세션 종료를 이유로 일지/인수인계 파일을 계속 추가하지 않고 상세 시험은 Validation에 연결한다.

## 자동화의 조건과 보류

기존 저장소 검사·PR 절차를 유지한다. 수동 V01 성공 후 검증된 Server/클라이언트 명령을 실행 ID·빌드 ID·자신이 시작한 PID·타임아웃·로그 수집과 묶는다. 이후 반복이 실제로 생기면 특정 시험 요약·누락 검사를 추가한다. 시험0건/비정상 종료를 성공으로 세지 않고 실제 게임 모듈의 클라이언트 요청을 사용한다. 자동 도구가 본인의 설명·기여·완료 판단을 생성하지 않게 한다.

대형 대시보드·상시 예약·전체 Gauntlet/클라우드 인프라는 현재 보류다. 반복 비용/오류를 관찰했을 때 도입 비용과 비교해 재검토한다. 게임 자동화는 이번 문서 보완에서 제작·실행하지 않았다.

### 대표 판단 사례 선택

원인을 확인하고 실제 행동을 바꿨으며, 변경 뒤 결과를 확인한 사례를 우선 선택합니다. 사례는 1~2개면 충분하며 의미 있는 변경이 없다면 억지로 채우지 않습니다.

학습 지연으로 기능 구현 순서를 바꾼 경우, 서버 문제 때문에 콘텐츠를 줄인 경우, 검증 실패로 제출 범위를 바꾼 경우는 후보 유형입니다. 아직 실제로 발생한 사건이라는 뜻은 아닙니다.

각 사례는 아래 순서로 편집합니다.

1. 어느 목표에서 어떤 문제가 드러났는지와 당시 근거.
2. 실제로 검토한 대응과 선택 이유.
3. 유지한 핵심, 포기한 가치, 바뀐 기한·완료 조건.
4. 본인이 한 판단·직접 수정·검증과 AI가 지원한 범위.
5. 조치 후 확인한 결과와 남은 한계.

“단순화해서 시간을 절약했다”는 문장에는 무엇을 줄였고 실제 결과가 어땠는지 붙입니다. 비교 측정이 없다면 절약 시간을 수치로 쓰지 않습니다.

### 최종 편집 전에 확인할 것

- 계획 날짜와 실제 완료 날짜, 최초 제외와 진행 중 축소가 구분됐는지.
- 최종 결과가 미완성이라면 검증된 기술 사례의 범위로 표현했는지.
- 코드·로그·영상·검증표의 버전과 조건이 맞는지.
- AI가 작성한 계획·코드를 본인 단독 작업으로 바꾸지 않았는지.
- 실패·보류·미검증·포기한 기능과 가치가 결과 가까이에 남아 있는지.
- 작성 양식과 미래형 문구를 실제 결과로 교체했는지.
- 최종 링크와 매체별 화면을 확인했는지.

현재 완료된 것은 기록 기반과 편집 구조 마련입니다. 게임 개발을 운영한 결과와 기존 포트폴리오 반영은 이후 실제 근거를 수집한 다음 작성할 항목입니다.
