## 데스크톱·노트북에서 직접 확인

두 PC에서 같은 `CoopRPG-MVP02-01-Forest.zip` 묶음을 풀고 `Start-CoopLan.ps1`과 `Stage`가 나란히 있는 폴더에서 PowerShell을 연다. 데스크톱은 서버와 A를, 노트북은 B를 실행한다. Tailscale 연결과 UDP 포트 환경은 [별도 PC 기준선](LanBaseline.md#manual-tailscale-20261118)을 사용한다.

**데스크톱 · 서버 및 A**

```powershell
$forestServerIp = (tailscale ip -4).Trim()
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Start-CoopLan.ps1 -Role Server -Map L_ForestExpedition -Address $forestServerIp
```

시작 출력의 `Log` 파일에서 `listening on port`와 `ForestStageReady Map=L_ForestExpedition`을 확인하고 A를 실행한다.

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Start-CoopLan.ps1 -Role Client -ClientLabel A -Address $forestServerIp
```

**노트북 · B**

```powershell
$forestServerIp = Read-Host '데스크톱의 Tailscale IPv4'
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Start-CoopLan.ps1 -Role Client -ClientLabel B -Address $forestServerIp
```

1. 두 창에서 숲의 시작 지점과 공용 상자가 보이는지 확인한다. 각자 `R`을 누른 뒤 `WASD`로 상자에 접근하고 `E`로 열어 `G`로 각자 무기를 받는다. `Q`로 상자 창을 닫는다.
2. A는 적의 정면에서 접근하고, B는 교전 공간 바깥쪽으로 돌아 적의 측면에 선다. 각 화면에서 적의 밝은 정면 표시와 두 플레이어가 함께 보이는지 확인한다. 카메라가 놓치는 곳이나 이동이 막히는 곳을 화면과 함께 남긴다.
3. 왼쪽 클릭으로 적을 처치한다. 처음 클릭하거나 다른 창에서 돌아온 뒤 첫 클릭이 포커스에 쓰이면 같은 창에서 다시 클릭한다. 적을 처치한 뒤 한 명이 전리품에 접근해 `T`를 누른다. 양쪽 팀 전리품이 `1`인지 확인한다. 한 명만 발판에 3초 이상 서서 진행이 시작되지 않는지 보고, 두 사람이 생존한 채 함께 올라 3초 동안 머문다.
4. 양쪽에 성공·1점이 보이면 결과 화면을 각각 저장한다. 데스크톱의 서버·A 로그와 노트북의 B 로그를 함께 남긴다. 시야와 우회는 교전 전에 찍은 A·B 화면도 함께 비교한다.

### 실행기에서 숲 서버 시작·종료

실행기의 `서버 맵`에서 패키지에 등록한 시작 맵을 고를 수 있다. 이번 묶음은 `L_Round_01`을 기본 선택으로 표시하고 `L_Movement`도 열 수 있다. 서버 실행 시 선택을 회차 기록에 저장하고, 실행기를 다시 열면 실행 중인 맵을 복원한다. 같은 패키지에서 마지막으로 고른 맵도 저장한다. 기존 패키지 정보에 맵 목록이 없으면 `L_Movement`를 사용한다. `접속 전용`의 클라이언트는 접속 대상 서버가 연 맵에 들어간다.

| PC | 기동과 확인 |
|---|---|

기존 GAS 비용·쿨다운·피해 효과를 사용한다. 피해 10, SP 비용 10, 쿨다운 2초다. 적용 전에 거절된 공격은 비용을 쓰지 않는다. 적용에 성공한 뒤의 빗나감과 타격 전 취소에는 비용·쿨다운이 남는다. 서버는 현재 적을 대상으로 공격 승인 시 정면을 고정하고, 타격 때 서버 위치에서 길이 145cm·반경 37cm의 구체 스윕을 한 번 실행한다. 앞선 월드 차단물과 유효 접촉을 대조하고, 같은 공격에서 적 컴포넌트가 여러 개 잡혀도 피해 효과는 한 번만 적용한다. 기존 고정 표적의 거리 기반 경로는 유지했다.

## 11/20 서버 스윕 표시와 취소 경계 검증

### 실제 스윕 표시

전용 서버와 두 클라이언트에 `-CoopMeleeSweepDebug`를 붙이는 Win64 Development 검증 모드다. 서버가 실제 질의에 사용한 시작점·끝점·반경과 가장 앞선 유효 접촉을 전달한다. 양쪽 화면에 길이 145cm의 중심 경로와 반경 37cm의 구체가 지나간 부피를 1.25초 동안 표시한다. 청록은 적중, 주황은 장애물 차단, 빨강은 스윕 실행 후 미접촉이다. 점은 유효 접촉이 검출됐을 때의 구체 중심이다. 취소나 거리 등의 선행 검사에서 멈춘 공격은 표시할 스윕이 생기지 않는다.

### 전용 서버와 클라이언트 두 개

같은 PC에서 `L_Round_01` 전용 서버와 렌더링 클라이언트 A(P1)·B(P2)를 띄웠다. 기존 입력으로 준비, 상자 무장, 왼쪽 클릭 공격, 오른쪽 클릭 취소를 실행했다. `-CoopCombatTest`로 표적과 공격 자세를 고정했고 중복 시험에만 충돌체를 추가하고 같은 타격 확정 함수를 두 번 호출했다.

| 조건·회차 | P1 타격 전 / 후 | P2 타격 전 / 후 |
|---|---|---|
| 기본 · `Base02/` | 23.33ms 전 / 16ms 후 | 12.24ms 전 / 65ms 후 |
| 클라이언트 수신 지연 100ms · `Lag01/` | 73.49ms 전 / 24ms 후 | 12.24ms 전 / 46ms 후 |
| 클라이언트 수신 손실 1% · `Loss02/` | 21.73ms 전 / 20ms 후 | 9.90ms 전 / 11ms 후 |

타격 전은 서버가 취소를 승인했을 때 타격 타이머의 남은 시간이다. 타격 후는 피해 확정 로그부터 서버의 첫 취소 요청 수신까지의 경과 시간이다. 입력을 예약한 시간과 실제 서버 수신의 순서를 구분하고 각 조건에서 서버 경계 75ms 이내 표본을 대조했다. 수신 지연·손실은 두 클라이언트에 각각 적용했고 서버 수신에는 추가하지 않았다.

- **타격 전 취소** · 양쪽 몽타주가 멈췄다. 해당 공격의 스윕과 피해 기록은 없었고 두 클라 모두 적 HP가 유지됐다.
- **타격 후 취소** · 서버가 무시했다. 적중 스윕 1건과 피해 10 한 건이 양쪽에 반영됐다. 양쪽 몽타주에 취소 중단은 없었다.
- **중복 방지** · 기본 회차에서 P1·P2 각각 적의 충돌체가 두 개 잡히고 같은 확정 함수를 두 번 호출해도, 서버는 스윕 1건과 피해 10 한 건만 기록했다. 양쪽 적 HP 변화도 각각 한 번이었다. 장애물 차단은 피해 0이었다.
- **표시 끔** · 같은 패키지의 별도 회차에서 스윕 계측 옵션 없이 P1 공격은 정상 적용돼 양쪽 적 HP가 100 → 90으로 바뀌었고, 서버 전송·클라 표시 로그는 없었다.

## 11/20 숲 라운드 종료와 재도전

사망·시간 초과 뒤 다른 맵으로 이동하는 동작을 현재 맵 재도전으로 바꿨다. 진행 중 접속 중단은 남은 플레이어에게 중단·0점을 표시한다. 성공 후에는 연결된 다음 맵이 있을 때 진행한다. 현재 숲 스테이지는 `L_Round_01` 한 개이므로 성공·1점과 `Expedition complete.`를 표시하고 결과 화면을 유지한다.

`8c378e0`을 기준으로 변경한 Win64 Development 전용 서버·클라이언트를 빌드했다. 직전 숲 패키지의 쿠킹 컨테이너 10개를 SHA-256으로 대조해 재사용했다. 한 PC에서 전용 서버와 클라이언트 두 개를 실행해 실제 준비·공격·획득 입력을 사용했다. 시험용 명령으로 적의 HP·위치, 플레이어의 초기 피격 조건과 시간 초과 시점을 구성했다. 전용 서버의 결과와 복제 로그 및 HUD를 대조했다.

| `L_Round_01` 조건 | 확인 결과 |
