### LFS 준비와 호출 버전 복구

- [공식 v3.8.1 릴리스](https://github.com/git-lfs/git-lfs/releases/tag/v3.8.1)의 Windows 설치 파일을 다운로드하고 공개 SHA-256 `7ac0422468f9cce06a7916156ed284f223527ed40e6d9ccf5fc0e89ad05b389c`와 대조한 뒤 실행했다. Authenticode 서명도 GitHub, Inc. / Valid를 확인했다. 설치 종료 코드 0이며 재부팅은 요구되지 않았다. 설치는 관리자 모드로 `C:\Program Files\Git LFS`에 배치됐고 설치기가 시스템 PATH 끝에 경로·GIT_LFS_PATH를 추가했다. 사용자 스킬·VS·SDK 구성은 변경하지 않았다.
- 설치 뒤에도 `git lfs`와 Git Bash가 기존 Git 동봉 3.7.1을 호출했다. 현재 프로세스의 PATH/GIT_LFS_PATH 갱신만으로도 바뀌지 않는 것을 실제 확인했다. 원인은 Git의 동봉 실행 파일 선택이며 3.8.1 단독 실행 성공을 준비 완료로 계산하지 않았다.
- `C:\Program Files\Git\mingw64\bin\git-lfs.exe` 원본을 `git-lfs-3.7.1.before.exe`로 보존했다. 일반 복사는 Windows 접근 권한 때문에 거절됐고 대상은 변경되지 않았다. 별도 관리자 helper로 공식 설치본과 같은 실행 파일을 동봉 경로에 복사한 뒤 양쪽 SHA-256 `7B38B496056A452EF1CE7DF3E3B5F18EF5E252C943F754CF22BFDDB59CA4DB1C` 일치를 확인했다. Git 본체·실행 래퍼는 교체하지 않았다. 향후 Git 재설치/업데이트가 동봉 LFS를 바꿀 수 있으므로 그때 호출 버전을 재확인한다.
- 최종 기본 Git·Git Bash 모두 `git-lfs/3.8.1 … git a662a6db`를 확인했다. `git lfs install --local`로 filter 설정 4개를 추가했고 기존 pre-push hook은 SHA-256까지 동일하다. 설치기가 실행한 전역 LFS 초기화의 filter 값은 기존 값과 같다. 로컬 설정·hook은 다른 PC에 자동 전달되는 파일이 아니므로 그 장비에서 다시 준비한다.

## R01 커밋 변경 검사 — 2026-11-02

P1 직접 실행의 기본값은 기존 작업 트리 검사다. 커밋된 변경까지 검사하려면 `-DiffBase <전체 40자리 SHA>`를 지정한다. 통합 CI 진입점은 비교 기준을 반드시 정하고 P1에 전달하며, 결과의 diffBaseSha·diffMode를 실행 전 기대값과 대조한다.

```powershell
# C:\CoopRPG, PR #1의 현재 원격 main 기준 전체 변경과 미커밋 변경 검사
pwsh -NoProfile -File .\Tools\Validation\Invoke-RepositoryCI.ps1 -DiffBase 58b0735972ff312481603ea15741f2397549bb3a
```

로컬 통합 기본값은 HEAD의 첫 부모이며 범위를 넓힐 때 명시적 SHA를 준다. GitHub PR은 test merge의 첫 부모=PR base·둘째 부모=PR head를 확인하고 base→실제 HEAD를 검사한다. main push는 이벤트 before→실제 HEAD를 검사해 여러 커밋의 push도 마지막 커밋만으로 축소하지 않는다. checkout은 fetch-depth=0으로 코드 이력을 확보하며 LFS 객체·서브모듈·인증 유지 비활성은 유지한다. 별도 네트워크 호출을 검증 스크립트에 추가하지 않았다.

비교 SHA 부재·잘못된 형식·자기 자신·비조상·객체 누락·PR 부모 불일치는 실패 처리한다. 최초 루트 커밋·before가 0인 신규 브랜치 push·강제 비선형 push는 현재 지원 범위가 아니며 자동 성공으로 대체하지 않는다. 해당 main 이벤트의 실제 원격 실행은 main 미병합 상태에서 아직 검증하지 않았고 로컬 Git 표본과 구분한다. 결과·시험 수·실제 원격 판정은 [R01 기록](Index.md#r01-커밋된-변경-검사-보완--2026-11-02)을 따른다.

## P1 저장소 검증기 실행 — 2026-10-30

**확인 범위:** DSYEOM의 PowerShell 7.6.5와 기존 Git에서 P1 로컬 저장소 검사·표본 검증을 실행했다. 후속 리뷰에서 검증기 1.0.1로 수정하고 회귀 29개를 확인했으며 [리뷰 결과](Index.md#p1-코드결과-리뷰--2026-10-30)를 따른다. 엔진 설치/변경·UE 실행·Actions·업로드는 하지 않았다. 판정 범위·표본 결과·원시 실행 ID·미확인은 [P1 결과](Index.md#p1-로컬-저장소-검증--2026-10-30)를 따른다.

### 후속 실행용 권장 구성

기존 UE 5.8.4·VS 2022 17.14.14·MSVC 14.44.35216·SDK 26100·동봉 .NET 10 조합을 유지한다. C: 페이지 파일 초기 32GiB(32768MB)·최대 64GiB(65536MB)를 사전 확보하는 안을 권장하며 정확한 값은 공식 최소·최적값이나 빌드 성공 보장이 아니다. 현재 자동 관리가 이번 오류의 직접 원인으로 확정된 것도 아니다. [Microsoft 크기 결정 기준](https://learn.microsoft.com/en-us/troubleshoot/windows-client/performance/how-to-determine-the-appropriate-page-file-size-for-64-bit-versions-of-windows)에 따라 실제 최대 커밋·덤프 요구·디스크를 함께 판단한다. 적용과 필요한 재부팅은 별도 허용 후 수행하고 실제 할당·한도를 재확인한다.

앞선 C: 207.99GiB에서 초기 32GiB는 현재보다 약 26.75GiB를 추가 사용해 약 181.24GiB, 최대 64GiB까지 증가하면 약 149.24GiB가 남는 단순 계산이다. 이후 엔진·OS·다른 작업 증가량은 제외했으므로 설치/빌드 가능 공간 확정값으로 사용하지 않는다.

엔진 루트 C:\UE\5.8.4에서 아래 구성을 후보로 사용한다. 최대 4작업은 상한이며 실제 동시 실행 수 보장이 아니다. 이전 산출물을 재사용하고 Setup·GenerateProjectFiles·전체 Clean을 반복하지 않는다. 2작업 고정은 초기 필수 조건에서 제외하며 회복 없는 압박으로 재시도가 필요할 때 다음 실행에서 낮춘다. 느리다는 이유만으로 정상 실행을 끊고 옵션을 연속 변경하지 않는다.

```bat
Engine\Build\BatchFiles\Build.bat UnrealEditor Win64 Development -WaitMutex -WindowsSDKVersion=10.0.26100.0 -MaxParallelActions=4 -NoUBA
```

이 명령은 재개 후보이며 이번 실행·성공 명령이 아니다. 재개 로그에서 실제 도구·옵션 적용을 확인하고, 전체 종료 코드 0·UnrealEditor.exe·UnrealEditor.target receipt와 해당 실행의 로그를 함께 확인해야 엔진 빌드 완료로 기록한다. 에디터 기동은 별도 후속 확인이고 게임·Server/Game·V01 성공으로 확대하지 않는다.

다른 세션·앱 전체 종료나 특정한 유휴 RAM 수치를 필수 조건으로 만들지 않는다. 필요한 앱은 유지하고 대규모 빌드·영상 처리 등 자원 경합은 사용자 일정에 맞춰 조정한다. 다른 작업을 임의 종료하거나 영상에 접근하지 않는다. 기존 미커밋 문서도 보존하며 그것만으로 엔진 재개를 차단하지 않는다.

## D01-S UE 5.8.4 환경 구성안 — 2026-10-30

작업 범위: 노트북에서 공식 릴리스·소규모 소스 설정 텍스트의 읽기 조회, 설치 정보 대조, 공간 예산 작성. 60분 상한의 조사 단위로 진행했고 주요 조회는 14:09~14:11 KST에 수행했다. 전체 소스/바이너리 다운로드·Git 초기화·설치·Setup·빌드는 하지 않았다. 아래 권고와 공간 예산은 구성안이며 실제 준비·시험 통과와 구분한다.

### 공식 소스 기준 — 확인 사실

| 항목 | 확인 근거·결과 | 한계 |

### 공간 예산 — 실측과 계획 배정 구분

**실측:** 2026-10-30 14:09 KST `Get-PSDrive`: C: 여유 **62.93GiB**, 사용 412.85GiB. 노출된 Temp도 같은 볼륨이다. 데스크탑의 디스크는 아직 측정하지 않았다.

**근거의 한계:** 열람한 공식 Windows 소스/빌드 안내에는 이 프로젝트에 적용할 고정 디스크 요구량이 없다. [하드웨어 안내](https://dev.epicgames.com/documentation/en-us/unreal-engine/hardware-and-software-specifications-for-unreal-engine)의 Epic 워크스테이션 디스크 사양을 최소 요구량으로 사용하지 않는다. 의존성 매니페스트는 메타데이터(36,681,163바이트·blob `002e0d5f19cc6cd89f5803030ddba1e37202281b`)만 조회했다. 그 크기는 내려받을 바이너리 크기가 아니며, 파일 필터·압축/해제·중복 캐시·빌드 타깃에 따른 실제 점유량은 미측정이다.

다음 수치는 **AI가 제안하는 용도별 초기 예약 예산**이다. 공식 최소치·실제 용량 예측·상한 보장이 아니다. Windows x64의 개발용 Editor·Server·Client, 작은 MVP 한 개를 위한 계획 배정이며 추가 플랫폼·디버그 전체 심볼·Installed Build 별도 제작·여러 엔진 사본은 포함하지 않는다.

|---|---:|---|

**운영 제안:** 데스크탑에서 엔진 준비를 시작하기 전 관련 볼륨 합계 약 **400GiB의 빈 공간**을 확보하는 것을 초기 목표로 삼는다(360GiB 배정 + 추가 여유 40GiB). 필수 장비 구매 조건이 아니며 공간이 적다면 실제 준비 범위·캐시·타깃을 다시 산정한다. 예산보다 실제 증가량이 크면 진행 범위와 저장 위치를 재판단한다. 현재 노트북 62.93GiB는 이 계획 예산에 미달하므로 노트북에서 전체 소스 준비·빌드를 시작하는 안은 권하지 않는다. 파일 정리·삭제·이동이나 저장 장치 구매는 수행하지 않았다.

### 공식 요구와 대조

2026-10-29에 버전별 공식 페이지를 열어 확인했다. [UE 5.5 VS 설정](https://dev.epicgames.com/documentation/en-us/unreal-engine/setting-up-visual-studio-development-environment-for-cplusplus-projects-in-unreal-engine?application_version=5.5)과 [UE 5.6 VS 설정](https://dev.epicgames.com/documentation/en-us/unreal-engine/setting-up-visual-studio-development-environment-for-cplusplus-projects-in-unreal-engine?application_version=5.6)은 VS 2022 최소 17.8, MSVC 최소·권장 14.38.33130, SDK 최소 19041·권장 22621 이상, .NET 8을 제시한다. VS 권장은 5.5에서 17.10, 5.6에서 17.14이며 IDE 버전과 MSVC 버전을 별도로 판단한다. 이 공식 표는 바이너리 엔진 통합 안내이므로 소스 후보의 전체 빌드 성공 보장은 아니다.

[UE 5.6 데디케이트 서버 안내](https://dev.epicgames.com/documentation/en-us/unreal-engine/setting-up-dedicated-servers-in-unreal-engine?application_version=5.6)는 소스 빌드 엔진과 클라이언트/서버 게임플레이를 지원하는 C++ 프로젝트를 전제로 한다. 이 공식 경로를 기준으로 소스·의존성 준비가 필요하다. 설치형 5.5.4의 존재만으로 해당 조건을 충족했다고 판단하지 않는다. 문서 예제의 Lyra를 CoopRPG의 필수 자산이나 설치 대상으로 채택한 것은 아니다.
