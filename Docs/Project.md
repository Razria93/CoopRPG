# 프로젝트 기준

작성일: 2026-10-29 · 현행 기준 갱신: 2026-11-05. 목적·범위·게임 규칙의 원본. 현재 상태와 남은 확인/선택/검증 사항은 [Roadmap](Roadmap.md), 검증 결과는 [Validation](Validation/Index.md)에서 관리한다.

## 문서 사용 기준

- **열람·수정 시점:** [AGENTS의 문서 책임](../AGENTS.md#문서-책임과-종료-보고)을 따른다. 범위·설계·시험 기대값을 정하는 사람이 참조한다.
- **포함·경계:** 목적, 사용자 조건, 포함/제외 범위, 게임 규칙, 비교·성과 표현 기준을 관리한다. 진행 상태·설계의 코드 설명·시험 결과를 복제하지 않는다.
- **최소 양식:** 항목마다 상태 구분과 내용을 명시하고, 규칙에는 적용 조건과 기대 동작을 쓴다. 채택·변경 근거는 Roadmap의 관련 결정으로 연결하며 미결정은 해당 ID를 참조한다.
- **검증:** 다섯 목적의 누락, 포함/제외 범위와 규칙의 충돌, 제안의 무단 확정, 사용자 진술의 실측 사실화를 확인한다. 채택할 규칙은 시험 기대값으로 판정 가능해야 하며 수치·경합 순서가 미정이면 미정으로 남긴다.

## 1. 상태 구분

| 표기 | 의미 |
|---|---|
| 확정 요구 | 사용자가 정한 목적·제약 또는 채택한 운영 체계 |
| 제안 | 아직 개별 결정되지 않은 게임 규칙·구조·일정·수치 |
| 채택 기준 | 사용자 허용 범위 안에서 주체·이유·적용 버전을 명시해 선택한 운영/기술 기준. 사용자 직접 발언·구현 완료와 구분 |
| 미결정 | 아직 선택하지 않은 사항. Roadmap의 ‘선택할 사항’에서 담당·시점·방법 관리 |
| 확인 사실 | 도구·파일·실행으로 확인한 결과. 날짜·방법·범위 명시 |

사용자 진술은 별도로 출처를 표시한다. 실측 결과와 혼동하지 않는다. 계획·문서 작성·코드 존재는 기능 통과의 근거가 아니다.

남은 일의 분류는 별도로 구분한다. **미확인 사실**은 자료·환경 조사로 확인할 정보, **선택할 사항**은 비교 근거로 채택할 결정, **검증할 가설**은 실행·측정으로 판단할 주장이다. 가설이 있다고 실행이 허용된 것은 아니며, 사실 확인이나 선택 완료만으로 가설이 검증되지는 않는다. 세 분류는 [Roadmap](Roadmap.md#남은-확인선택검증-사항)에서 관리한다.

## 2. 확정 요구

1. **기술 역량:** GAS와 데디케이트 서버 구현 경험을 실제 협동 액션 RPG·파밍·탈출 콘텐츠로 입증한다. 서버 경험은 UE 서버 타깃 빌드·실행·접속·서버 권한 게임플레이의 범위로 설명한다.
2. **다음 단계의 포트폴리오:** GAS를 의도적으로 사용하지 않은 스텔라의 자체 전투 구조 경험을 토대로, 같은 문제를 GAS에서 어떻게 해결하는지 비교한다. 단순 병렬 프로젝트가 아니라 언리얼 활용 역량 확장이 목적이다.
3. **AI 활용:** 콘텐츠 제작에서 작업 정의·맥락 제공·구현·검토·수정·검증을 체계적으로 수행하고 본인의 판단과 AI 기여를 구분한다. 업계 사례를 참고하되 채용 전체의 보편 기준으로 과장하지 않는다.
4. **문서화:** 목적·계획, 구조·구현, 문제 해결, 검증, 증거를 필요한 만큼만 기록한다. AGENTS와 최소 문서 체계를 사용하며 중복 인수인계 문서를 늘리지 않는다.
5. **MVP 통제:** 넷마블네오 지원 목표에 맞춰 작은 실행 단위로 학습·개발·검증·기록을 진행하고 범위·기한 변화와 손실을 남긴다. 현행 제출 목표는 11월 23일, 공식 마감은 11월 24일 23:59이며 달력·게이트는 [Roadmap](Roadmap.md#delivery-calendar)을 따른다. 과거 4주 목표는 당시 이력으로 보존하고 현재 납기와 혼용하지 않는다.
6. **작업 위치·현재 제약:** 루트는 `C:\CoopRPG`다. 현재 허용 작업과 임시 자료 보존 규칙은 [AGENTS](../AGENTS.md)를 따른다.

핵심 결과는 작은 게임의 완주와 기술 검증이다. AI 운영 체계·문서·자동화가 별도 대형 산출물이 되어 콘텐츠 완성을 밀어내지 않게 한다.

## 4. 7단계 MVP 범위 — 2026-11-14 갱신

두 플레이어가 상자에서 전투를 준비하고, 적을 처치해 얻은 전리품을 탈출로 확정한 뒤 다음 라운드 맵으로 이동한다. 사용자가 7단계와 공용 상자·전리품 규칙을 정했다. 아래의 보상 수량·점수 방식·다음 맵 구성은 구현과 시험을 위한 제안이다.

| 단계 | 범위 | 완료 기준 |
|---|---|---|
| 1. 전용 서버 접속 | 패키지 Server 1개·Client 2개 | 두 클라이언트가 접속하고 각자 자기 Pawn을 조작한다. |
| 2. 이동·액션·상태 동기화 | 기본 이동·GAS 근접 단타·HP·스태미나·쿨다운 | 서버 승인·거절·취소와 재실행을 확인하고 양쪽 클라이언트가 필요한 상태를 받는다. |
| 3. 공용 상자 루팅 | 근접무기 1종과 회복약 1종 | 두 사람이 같은 상자를 동시에 열 수 있다. 마지막 회복약은 서버가 처음 처리한 유효 요청의 플레이어만 받는다. 무기 장착과 회복약 사용 결과를 확인한다. |
| 4. 적과 전투 및 승리 | 최소 적 1종의 서버 공격·피격·사망 | 두 플레이어의 타격이 가까운 시점에 들어와도 적 사망이 한 번만 확정된다. |
| 5. 적 전리품 루팅 | 사망 때 한 번 생성되는 팀 보상 | 어느 플레이어가 먼저 유효하게 획득해도 팀에 한 번 지급한다. |
| 6. 탈출 및 점수 확정 | 두 명의 공동 탈출·결과 화면 | 서버가 탈출 결과와 팀 점수를 한 번 확정하고 두 클라이언트에 표시한다. |
| 7. 다음 라운드 맵 이동 | 서버 주도 맵 이동과 다음 라운드 준비 | 두 클라이언트가 같은 다음 맵에 도착해 각각 자기 Pawn을 조작할 수 있고 새 라운드가 준비된다. |

1~6단계가 이어지면 한 맵에서 한 판을 완주한 상태다. 7단계까지 검증하면 7단계 MVP를 통과한다. 제출에는 실제 패키지에서 확인한 범위를 표시한다. 콘텐츠는 공통 캐릭터, 고정 맵과 최소 자산을 사용하고 이용·배포 조건을 확인한다. 최소 UI는 HP·스태미나·장착 무기·회복약·팀 전리품·타이머·탈출 진행·점수·연결 상태를 보여준다.

**범위 밖** · 장비 슬롯 확장·무기 교체·범용 인벤토리·제작·거래, 랜덤 드롭/맵, 다운·부활, 대시·회피·콤보·패링·락온·보스·추가 직업, 영구 저장·계정·매칭·재접속 복구, PvP·대규모 동접·범용 롤백·클라우드 배포.

**근거** · [최초 계획 보존본](Planning/Baseline-20261105.md#mvp) · [11월 14일 변경 기록](Development.md#mvp-revision-20261114) · [구현·검증 순서](Roadmap.md#mvp-implementation-order)

### 1차 MVP 마감과 2차 후보

2026-11-16 사용자 채택. 1차는 두 사람이 게임 화면의 안내로 준비하고 무장·전투·루팅·공동 탈출을 거쳐 새 라운드에서 다시 준비할 수 있는 상태까지 진행한다. 상자 거리 이탈 닫기와 무기·회복약 재고 로그, P1·P2·적 식별과 피격·획득·사용·회복 표시, 탈출 상태와 남은 시간, 결과·점수·스테이지, 양쪽 준비 상태를 포함한다. 최종 패키지에서 기본 조건의 성공·실패 후 재준비, 기동 안내 재현과 [제출 전 V08 핵심 시험](Validation/Index.md#pre-submission-v08)을 확인한다.

2차 후보는 맵·메시·이동 동선, 무기·애니메이션·충돌·피해 처리, 아이템 습득·사용·소비·버리기, 상자 내용물 시각화, 게임 UI·효과음, 트러블슈팅·확장 검증·문서화다. 1차 결과를 보고 범위와 순서를 정한다.

## 5. 게임 규칙 M1 — 2026-11-14 갱신

| 조건 | 동작·기대값 |
|---|---|
| 접속·시작 | 서버가 정원2를 관리. Waiting에서 두 명의 준비가 모이면 Playing. Playing 중 신규 참가·정원 초과 거절 |
| 권한 | 피해·수집·탈출·시간·결과는 서버 확정. 요청자 소유권·상태·거리/대상·중복을 검사. UI 차단만으로 대체하지 않음 |
| 공격 | Ability 실행 조건·비용·쿨다운을 Commit 단계에서 검사. Commit 전 거절은 최종 비용/피해 없음. Commit 후 빗나감·취소에는 비용/쿨다운 유지 |
| 취소·사망 | 서버 피해 확정 전에 취소를 수락한 공격은 피해0. HP0은 사망이며 다운/부활 없음. 실행 소유의 임시 Tag/Effect·타이머/콜백 정리, 의도적 비용/쿨다운은 유지 |
| 공용 상자 | 두 사람이 동시에 내용물을 열람한다. 상호작용 거리 밖으로 나가면 서버가 이탈한 플레이어의 열람만 종료한다. 범위 안으로 돌아온 플레이어가 다시 열기를 요청할 수 있다. 서버는 Playing 여부, 요청자 생존, 대상·거리·현재 라운드와 남은 수량을 확인한다. 마지막 회복약은 서버가 먼저 처리한 유효 요청의 플레이어에게만 지급하고 두 화면의 상자 목록에서 회복약을 제거한다. 중복·소진·이전 라운드 요청에 추가 지급은 없다. |
| 적 전리품 | 서버가 적의 생존→사망 전환을 한 번 확정할 때 전리품을 한 번 생성한다. 유효한 획득 한 건으로 팀 전리품 수량을 올리고 양쪽에 복제한다. |
| 탈출·점수 | 팀 전리품 목표를 충족하고 두 사람이 생존한 채 구역에 연속 3초 머물면 성공한다. 이탈하면 진행을 0으로 되돌린다. 두 사람이 생존하고 구역을 유지하면 피격 후에도 진행이 이어진다. 서버가 성공 결과와 팀 점수를 한 번 확정한다. |
| 실패·중단 | 한 명 사망 또는 5분 만료는 실패·0점이다. 진행 중 접속 종료는 중단·0점이고 서버 종료는 클라이언트에 연결 종료 안내를 표시한다. |
| 라운드 진행·재도전 | 성공 후 연결된 다음 맵이 있으면 진행한다. 다음 원정 맵이 준비될 때까지 숲에서 성공하면 결과를 유지한다. 사망·시간 초과는 두 사람이 결과를 확인한 뒤 같은 맵에서 새 라운드로 재준비한다. 접속 중단은 결과와 안내를 유지한다. |
| 종료 경합 | 서버의 같은 라운드 판정 회차에서 이탈 중단 → 사망 실패 → 시간초과 실패 → 탈출 성공 순서. 이미 확정된 Result는 다시 바꾸지 않음. 종료 판정 뒤에는 전투/획득 거절 |
| 다음 라운드 | 결과를 두 클라이언트에 표시한 뒤 서버가 다음 맵 이동을 시작한다. 새 라운드에서 HP·스태미나·비용·쿨다운·무기·회복약·적·상자·팀 전리품·타이머·탈출·준비 상태를 초기화하고 라운드 식별값을 갱신한다. 두 명이 도착해 준비하면 Playing으로 전환한다. |
| 표현·판정 | 로컬 반응과 서버 피해 확정은 구분. 타격을 클라이언트 애니메이션/렌더링에만 의존하지 않음. 예측 범위와 거절 복구는 D06-S에서 구현 전에 선택 |

첫 구현 제안은 두 사람이 같은 종류의 근접무기를 하나씩 확보할 수 있게 배치하고, 경합용 회복약 1개와 적 전리품 1개를 두는 것이다. 전리품 1개로 탈출 조건을 충족하고 성공 시 팀 점수 1점을 확정하는 안을 사용해 시험을 설계한다. 직전 점수는 결과 화면에 표시하고 다음 라운드 점수는 0으로 시작하는 안이며, 다음 맵은 첫 맵 배치를 재사용할 수 있다. 수량·점수·맵과 능력 세부 값은 해당 작업의 시험 기대값을 정할 때 확정한다. 고정 표적 HP 100·피해 10은 V02 시험값이다. 첫 단타에는 수평 사거리 250 cm, 캐릭터 스태미나 100, 승인 비용 10을 AI 구현 판단으로 사용한다. 2026-11-15 사용자가 단타 쿨다운 시험값 2초를 채택했다. 정상 승인 시 비용과 함께 적용하고 거절 요청으로 연장하지 않는다. 실제 전투 밸런스는 미검증이다. <a id="expedition-default-equipment"></a>
### 직업 기본 장비와 개인 장비 · 2026-11-23 채택

전사는 기본 한손검, 수호기사는 기본 한손검과 방패를 장착한다. 로비와 전투에서 개인 장비가 장착된 슬롯은 개인 장비를 사용하고, 해제하면 그 슬롯의 기본 장비로 돌아간다. 현재 개인 장비는 한손검을 지원한다. 수호기사는 개인 한손검과 기본 방패를 함께 사용할 수 있다.

기본 장비는 가방·창고의 아이템 수량에 포함되지 않는다. 개인 한손검은 최초 장착 시 귀속되고 해제 후에도 귀속을 유지한다. 로비 복귀와 다음 원정에 개인 장비와 장착 선택을 이어가며, 같은 스테이지 재도전은 입장 시점의 장착 선택을 복원한다. [실제 적용과 시험 범위](Roadmap.md#expedition-default-equipment-work)

### 수호기사 · 도발

잡몹전과 흑기사전에서 수호기사가 방패를 장착한 상태로 3번 슬롯을 사용한다. 가드 중에도 발동할 수 있다. 시전자 발밑을 중심으로 반경 400cm 안에 충돌체가 걸치고, 높이 차가 100cm 이하이며 지형에 막히지 않은 생존 적의 우선 대상을 4초 동안 시전자로 바꾼다. 유효한 적이 하나 이상 있을 때 SP 15를 소모하고 12초 쿨다운이 시작된다.

이미 시작된 공격과 흑기사 반격의 대상·방향은 해당 공격이 끝날 때까지 유지한다. 효과가 끝나거나 시전자가 전투에서 이탈하면 평소 대상 선택으로 돌아간다. [시험 결과](Validation/ForestExpedition.md#guardian-taunt-verification)

## 6. 스텔라 비교와 재사용 방향 — 제안

비교 축은 실행 조건·취소·정리, 자원·상태, 권한·예측·복제다. 각 축에서 이전 자체 구현, GAS 제공 기능, 여전히 직접 책임지는 코드, 선택의 장점·제약을 설명한다. GAS를 썼다는 사실만으로 품질·생산성 향상을 주장하지 않는다.

기존 구현 근거가 없는 기능은 일대일 비교를 만들지 않고 이번에 새로 습득한 범위로 표시한다. 과거에 같은 기능을 구현했다고 소급하지 않는다.

기존 규칙·종료 불변 조건·결함 사례·검증 방법을 우선 참고한다. 전체 프레임워크 자동 이식은 하지 않는다. 원본 자산과 프로젝트 전용 Notify·컴포넌트 의존성을 구분해 최소 자산만 선별한다. 재사용 가능성은 [환경 기록](Validation/Environment.md)의 검토 범위와 제한을 따른다.

## 7. 문서와 AI 성과의 표현

사람의 요구 정의·설계 판단·검토·실행 확인과 AI의 분석·구현·시험을 작업 기록에 구분한다. 중요한 사례가 생기면 `Cases`에 문제→원인→판단→수정→재검증을 남긴다. 전 대화·프롬프트를 수동 복제하거나 모든 함수의 설명서를 만들지 않는다.

사례에는 사용한 AI 도구(모델은 확인 가능한 경우), 맡긴 범위, 사람의 판단, 실제 검증 근거를 연결한다. 검토나 문제 해결을 AI가 수행했다면 그대로 기록한다. 생산성 수치 없이도 요구를 검증 가능한 결과로 연결한 과정은 설명할 수 있다. 다섯 목적의 최종 확인 기준은 [검증 색인](Validation/Index.md)의 목적별 근거를 따른다.

[Online Programmer](https://jobs.smartrecruiters.com/Ubisoft2/744000156044259-online-programmer-online-service-hosting-platforms)는 AI 보조 조사·반복 작업 자동화·문서화를 제시했다. 후자는 온라인 서비스 지원 직무다. 이는 사례이며 국내 UE 신입의 보편 필수조건이나 채용 통계가 아니다.

[Ubisoft 채용 AI 지침](https://www.ubisoft.com/en-us/company/careers/working-at-ubisoft/using-generative-ai-in-your-ubisoft-job-application)은 실제 경험과 본인 판단을 강조한다. 본 프로젝트에서는 AI 사용량보다 결과를 설명·수정·검증하는 능력을 입증한다. 과제·면접은 각 회사의 허용 규칙을 따른다.

## 8. 학습·채용 목적과 제출 근거

Part1~4는 개념 이해와 직접 수정 능력을 확보하기 위한 수단이다. 필요한 강의 → 작은 변형 실습 → MVP 적용 → 자기 설명·실행 확인으로 진행한다. 전체 완강·영상 시간·AI 코드량을 이해나 완성의 증거로 삼지 않는다. 날짜별 핵심37강·약25시간47분의 최초 배정은 [보존본](Planning/Baseline-20261105.md#learning), 실제 수강/설명/수정/검증은 [Development](Development.md#learning-operation)에 남긴다. 전체 과정 약40시간36분은 영상 길이이며 실습·재시청·버전 차이 대응을 포함하지 않는다.

[넷마블네오 공고](https://ai-internship2026.netmarbleneo.com/)와 2026-11-05 제공 이미지/앞선 조사에 따르면 2027년2월 졸업예정 또는 기졸업, 2027년3월부터 인턴 기간 풀타임 가능 조건이 있다. **본인의 해당 여부는 미확인**이다. AI 리더십·구조화·학습 실행력과 AI 활용 산출물/프로그래밍 이해를 프로젝트 근거로 연결하며 GAS·DS를 공고의 명시 필수 스택이나 합격 보장으로 표현하지 않는다. 제출 형식·용량·AI 활용 시험 규칙은 해당 안내를 확인한다.

PDF·웹·GitHub는 같은 규칙/코드·빌드/시험 근거와 기여를 공유한다. 완성 결과를 먼저 제시하고 대표 범위/일정 판단1~2건을 연결한다. 매일 모든 매체를 재편집하지 않으며 [기록과 최종 표현 기준](Development.md#portfolio-output)을 따른다.
