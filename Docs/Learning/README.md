# 강의 학습 노트 · 작성 기준

CoopRPG · 2026-11-06 · 잠정 양식

이 폴더는 언리얼 네트워크·GAS 강의를 복습하고 CoopRPG 구현에 필요한 원리와 코드 위치를 다시 찾기 위한 자료다. 현재 실습 기준은 리슨 서버이며, 전용 서버 전환은 실제 작업 단계에서 별도로 확인한다.

## 문서의 역할

- 강의별 노트는 강사가 설명한 원리, 예제 코드, 실행 흐름, 복습할 질문을 기록한다. 강의 수강만으로 직접 구현·검증했다고 쓰지 않는다.
- 프로젝트의 실제 학습 진도·직접 변경·판단은 [Development](../Development.md#learning-operation), 게임 시험 결과는 [Validation](../Validation/Index.md)에 기록하고 여기서는 링크한다. 동일한 결과를 여러 원본으로 관리하지 않는다.
- 여러 차시에 걸친 주제별 정리는 반복 내용이 쌓이고 실제로 찾아볼 필요가 생길 때 추가한다. 빈 주제 문서를 미리 만들지 않는다.

## 작성·검토 규칙

1. 강의 제목·링크, 예제 버전·브랜치, 노트의 근거 범위를 먼저 기록한다. 확인하지 않은 버전·파일 경로·실행 결과는 추정해 채우지 않는다.
2. 그 강의가 답하는 질문을 첫머리에 쓰고, 답을 짧게 정리한다. 개념은 정의와 함께 필요한 이유·적용 조건·혼동하기 쉬운 경계를 설명한다.
3. 코드가 중요하면 실제 파일·클래스·함수와 역할을 적고 예제 소스와 대조한다. 짧은 코드 발췌에는 출처를 붙인다. 자막에서 언급한 코드와 파일에서 확인한 코드를 구분한다.
4. 서버·리슨 호스트·원격 클라이언트의 실행 위치와 시점이 결과를 바꾸면 나란히 설명한다. 순서나 소유 관계가 글만으로 불명확할 때만 Mermaid 다이어그램을 쓴다.
5. 강의의 시연, 사용자의 직접 실습, 프로젝트에 적용한 결과, 공식 문서에서 확인한 내용, 앞으로의 제안을 혼동하지 않는다. 검증을 하지 않은 항목에 통과 판정을 쓰지 않는다.
6. CoopRPG 적용 메모에는 현재 필요한 연결만 적는다. GAS나 전용 서버에 관한 추가 내용은 강의 내용으로 둔갑시키지 않는다. 전용 서버에서 다시 확인할 조건은 발견했을 때만 표시한다.
7. 강의 내용을 전사하지 않는다. 나중에 원리·코드·조건을 재구성하는 데 필요한 설명을 남기고, 긴 구현과 원시 로그는 원본으로 연결한다.

## 제작 도구와 순서

1. 강의 페이지의 스크립트·설명에서 전체 흐름과 시간대를 확인한다.
2. 코드 설명이 필요한 곳은 강의에서 지정한 예제 브랜치와 로컬 코드를 확인한다. 추가 기술 주장은 해당 엔진 버전의 공식 자료와 대조한다.
3. [노트 양식](Template.md)을 복사해 Markdown으로 작성한다. 해당하지 않는 선택 항목은 삭제한다.
4. 링크·코드 식별자·서버/클라이언트 위치·근거 상태를 검토한다. 프로젝트 실행이나 검증을 하지 않았다면 그렇게 적는다.
5. 파일럿에서 다시 읽기와 코드 찾기가 어려운 지점을 확인한 뒤 이 양식을 조정한다. 반복 비용이 확인되기 전에는 생성기·자동화를 만들지 않는다.

## 파일럿 판정

[Part3 3강 파일럿](Part3-03-connection-ownership.md)은 양식 검토용이다. 노트만 읽고 핵심 원리와 서버/클라이언트의 차이를 설명할 수 있는지, 예제 코드의 확인 상태를 알 수 있는지, 프로젝트에 적용할 때 남은 확인을 찾을 수 있는지 평가한다. 자막 기반 초안은 코드·게임 실행 검증 완료로 판정하지 않는다.

첫 검토 결과(2026-11-06): 초기화·연결·오너십의 관계와 서버/클라이언트별 흐름은 노트에서 다시 찾을 수 있다. 반면 정확한 예제 파일 경로와 UE 5.8.4 적용 코드는 아직 찾을 수 없다. 따라서 현재 양식은 복습용 초안으로 유효하지만 구현 참조 문서로는 미완성이다. 다음 검토에서는 브랜치 3 소스를 대조해 함수 위치를 채우고, 사용자 실습이 진행되면 실제 로그·프로젝트 코드와 연결한다. 그 전에는 실습 완료나 구현 검증으로 판정하지 않는다.
