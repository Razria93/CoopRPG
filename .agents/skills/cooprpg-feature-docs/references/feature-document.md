# 기능 문서 양식과 편집 기준

이 파일은 작성 양식이다. 사건·역할·시험 결과가 아니다. 새 주제 문서나 큰 절을 구성할 때만 참고하고, 기존 문서의 작은 수정에는 필요한 부분만 적용한다. 주제의 생성·분리 기준은 [Development](../../../../Docs/Development.md#feature-documents)가 원본이다.

## 상단에서 답할 것

- 프로젝트·주제·문서 갱신일, 적용 작업 ID와 코드 기준.
- 독자가 이해할 결과와 현재 완료 범위 1~2문장.
- 구현·검증 대기 항목과 실행 환경처럼 결과 해석에 필요한 조건.
- 긴 문서에만 읽는 순서와 앵커를 둔다. 작업 날짜나 파일 이름만으로 제목을 정하지 않는다.

## 본문의 기본 전개

| 순서 | 담을 내용 | 원본·중복 방지 |
|---|---|---|
| 결과와 목표 | 어떤 플레이를 위해 무엇을 만들었고 현재 어디까지 확인했는가 | 범위는 Project·Roadmap을 연결 |
| 규칙·실패 조건 | 요청을 승인/거절하는 기준, 권한·소유권·수명과 핵심 불변 조건 | 구현 코드와 독립된 게임 규칙에서 기대값 도출 |
| 구조·데이터 흐름 | 입력부터 판정·상태 변경·복제·표시까지, 주요 클래스·함수의 역할 | 전체 구조는 Architecture; 필요한 코드만 발췌 |
| 선택과 대안 | 실제로 고민한 방법, 선택 이유, 비용과 포기한 가치 | 중요한 사건은 Development/Cases 기록을 연결 |
| 학습 적용과 기여 | 이해가 부족했던 점, 학습 근거, 적용 변화, 사용자·AI의 실제 행위 | 강의 노트를 복사하지 않고 적용 차이 설명 |
| 검증과 한계 | 조건·기대값·실제 결과·판정, 실패/복구·미실행, 다음 확인 | 상세 로그와 반복 결과는 Validation 원본 연결 |
| 근거 및 더 읽기 | 코드·시험·공식 문서에서 무엇을 확인하는지 | 결론 근거와 추가 학습 자료 구분 |

해당하지 않는 항목은 생략하거나 합친다. 실제 비교하지 않은 대안·실패·역할·절감 시간을 양식 때문에 만들어내지 않는다. 공개 본문에서 작업자의 내부 체크리스트나 대화 전문을 그대로 나열하지 않는다.

## 네트워크·GAS 흐름도

실행 위치(소유 클라이언트/서버/관찰 클라이언트)와 처리 주체를 표시하고, 성공·거절·취소 중 실제 구현한 경로를 그린다. 미구현 경로는 제안임을 밝히거나 현재 구조 그림에서 제외한다. 판정, 함수 호출, RPC, 속성 복제를 같은 화살표 의미로 섞지 않는다. 여러 함수를 대표 단계로 요약하면 그 사실을 밝힌다.

현재 GAS 문서의 실행 위치별 구획·분기·복제선과 PDF의 승인된 도식 의도는 보존한다. 가독성 때문에 나눈 그림은 연결점을 표시한다. 새로운 그림을 만들 필요가 없는 수정에는 기존 그림을 유지한다.

## 사례에 붙이는 최소 근거

아래 항목은 중요한 사건에만 사용한다. 일상 기록·인계 원본을 따로 늘리지 않는다.

```text
문제와 목표: 실제로 어떤 조건에서 무엇이 필요했는가
책임: 사용자와 AI가 각각 실제로 한 일, 위임한 범위
판단: 당시 고려한 대안, 선택 주체·이유·포기한 가치
학습: 부족했던 개념 → 확인한 자료 → 구현/검증에서 달라진 점
성과: 기대값 → 실제 관찰 → 근거 → 확인 범위와 한계
일정: 당초 목표·기한 / 실제 완료·이월 / 다음 확인 시점
```

AI 리더십·구조화 능력·학습 실행력은 이 사건으로 입증할 수 있는 것만 설명한다. 책임·판단·성과는 사례의 전개 방식이다. 사용자가 직접 확인하지 않은 부분은 AI 확인 또는 미확인으로 남긴다.

## 검수 기준

- 변경 후 코드와 설명이 일치하고, 기존 시험 재사용 조건과 새 시험을 구분했는가.
- 다른 사람이 문서만으로 재현할 수 있는 기대 결과·절차·근거에 도달하는가.
- 전문 용어를 먼저 정의하고 핵심 코드만 보여 주며 실패·미실행을 가까이 표시했는가.
- 링크·앵커·도식의 연결과 범례를 확인하고, 공개 편집본은 실제 렌더로 넘침·읽기 순서를 확인했는가.
- 기존 절·앵커를 살리고 README 판본 색인에서 편집 원본과 출력본을 찾을 수 있는가.

이 양식을 작성했다는 사실은 기능 완료·사람 검증·채용 역량 입증의 근거가 아니다.
