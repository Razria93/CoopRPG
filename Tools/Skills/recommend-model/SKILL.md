# 작업별 모델 추천

현재 작업에 적합한 설정을 짧게 추천한다. 추천은 운영 가설이며 성능 보장이 아니다. 선택 절차를 실제 작업보다 크게 만들지 않는다.

## 판단 절차

대화·작업 카드·관련 자료에서 목표/완료 기준, 현재 모델/추론, 오류 영향·재작업 비용, 시스템 간 상호작용, 검증 가능성, 이전 실패와 새 증거, 사용자의 시간·사용량 제약을 파악한다. 이미 있는 정보를 다시 묻거나 프로젝트 전체를 무조건 읽지 않는다. 현재 설정은 사용자 진술이나 확인 가능한 메타데이터에 근거하고, 없으면 미확인으로 표시한다. 가능한 조건부 추천을 먼저 제공한다.

작업 자체가 조사라면 아직 수집하지 않은 정보는 조사 대상이며, 이를 이유로 추천을 보류하지 말고 자료 수집 작업에 맞는 모델을 추천한다. 반면 분석·수정에 필요한 버전/코드/로그나 재현이 빠졌거나 요구 충돌·과도한 작업 범위가 있으면 자료 확보·작업 분할을 우선한다. 빌드 대기·도구 접근 문제를 추론 부족으로 취급하지 않는다. 자료 해석 자체가 어렵다면 상향도 별도로 검토한다.

## 추천 범위

아래는 사용자가 채택한 초기 후보이며 검증된 성능 순위나 모든 환경의 지원 목록이 아니다.

| 모델 | 추론 | 적합한 작업 |
|---|---|---|
| GPT-6.1 Sol (`gpt-6.1-sol`) | Medium (`medium`) | 요구가 명확하고 파일·관측 결과로 쉽게 대조할 수 있는 조사·문서·단순 수정 |
| GPT-6.1 Sol (`gpt-6.1-sol`) | High (`high`) | 구조·완료 기준이 정해진 기능 구현·시험 작성·국소 결함 수정, 여러 근거·제약을 대조하는 기술 구성안 비교 |
| GPT-6 Astra (`gpt-6-astra`) | High (`high`) | 오류 영향이 크거나 검증이 어려운 핵심 설계·복잡한 결함·중요 리뷰. 예: GAS 수명·서버 권한·예측/취소 |
| GPT-6 Astra (`gpt-6-astra`) | Extra High (`xhigh`) | 자료와 문제 범위를 충분히 정리했는데도 High에서 해결되지 않은 복잡한 분석에 한정 |

- 일반 작업은 Sol Medium, 기능 구현은 Sol High를 출발점으로 삼는다. 핵심 판단은 Astra High로 바로 시작할 수 있다. 하위 설정에서 먼저 실패하도록 요구하지 않는다.
- 작업 도중에는 진행 근거와 전환 부담을 우선 비교하고, 현재 설정이 적합하면 유지를 추천한다. 새 작업 시작 시에는 필요한 능력과 사용량을 우선 비교해 단순·반복 작업의 하향도 검토한다. 후보 밖의 현재 설정을 무조건 교체하지 않는다.
- 동일 결함 재발·수정마다 다른 경로 파손·핵심 요구 반복 누락·증거 없는 수정 반복은 상향 검토 신호다. 새 증거 없는 두 차례 수정은 접근법 재검토의 예시이며 자동 교체 규칙이 아니다. 실패하면서도 원인을 좁히면 유지할 수 있다.
- 구조·규칙·정상 패턴·검증 방법이 확보되면 Sol로 돌아갈 수 있다. 파일 수나 코드량만으로 난이도를 정하지 않는다. 서로 다른 모델의 같은 추론 이름이 같은 능력·사용량을 뜻한다고 가정하지 않는다.
- 기본 후보를 임의로 늘리거나 신모델로 자동 대체하지 않는다. 후보 사용이 불가능하면 확인된 후보 내 대안을 검토하고, 불명확하면 조건부 추천으로 남긴다.

## 근거와 비용

추천 후보와 실제 사용 가능 설정을 구분한다. 환경 메타데이터나 사용자가 확인한 선택 목록을 활용하고 미확인 지원 여부를 단정하지 않는다. 현재 가격·제품 지원·모델 성능에 관한 사실이 판단에 필요하면 공식 자료를 확인한다. `openai-docs`가 제공되면 해당 지침을 사용하며, 없으면 아래 공식 자료를 활용한다. 같은 세션의 관련 확인 근거는 재사용할 수 있지만 낡은 정보를 현재 사실로 쓰지 않는다.

- 모델·추론: https://learn.chatgpt.com/docs/models
- 선택·평가: https://developers.openai.com/api/docs/guides/model-selection

단순 작업 분류 때문에 매번 전체 모델 목록·가격표를 조사하지 않는다. 프로젝트 실측·공식 안내·자신의 추론을 구분한다. 정확도·속도·절감률·신뢰 확률을 근거 없이 수치화하거나 API 단가로 구독 한도를 환산하지 않는다. 비용은 AI 처리뿐 아니라 도구 실행·사람의 리뷰·수정·재검증을 포함한 완료 시간과 확인 가능한 사용량으로 평가한다.

## 출력과 경계

일반적으로 다음 네 항목으로 짧게 답하고 필요한 설명만 덧붙인다.

- **판단:** 현재 설정 유지 / 추론 수준 조정 권장 / 모델 변경 권장 / 자료 확보·작업 분할 우선 중 하나.
- **권장 설정:** 후보 중 한 조합 또는 확인된 현재 설정. 작업 범위·완료 기준을 파악하기 어려워 추천 근거가 부족할 때만 보류하거나 조건부 후보 하나를 제시한다. 사용 가능 여부 미확인은 표시한다.
- **근거:** 오류 영향·검증 가능성·현재 막힘·총 작업 비용 중 중요한 1~2개.
- **다시 판단할 조건:** 필요한 자료 또는 상향/하향 검토의 관측 신호 하나.

이 스킬은 추천만 수행한다. 모델·추론·기본 설정 파일 변경, 새 채팅 생성, 다른 모델 실행·하위 에이전트 호출, 비교 벤치마크 실행, 게임 구현·시험을 수행하지 않는다. 본 작업의 권한을 확장하지 않는다. 자동 호출되더라도 변경 확인 질문을 반복하거나 원래 허용된 작업을 불필요하게 멈추지 않는다. 추천과 적용을 구분하고 변경했다고 보고하지 않는다.

추천마다 문서를 만들지 않는다. 중요한 전환을 기록할 때도 기존 작업 기록에 이유와 실제 결과만 짧게 남긴다. 모델 간 동의는 정확성 증거가 아니며 최종 판단은 요구·코드·실행 결과에 근거한다.
